РУКОВОДСТВО ПОЛЬЗОВАТЕЛЯ
Автоматизированная система мониторинга и диагностики серверов «ServerMonitor Enterprise v2.0»

1. Введение
1.1. Область применения
Настоящее руководство пользователя распространяется на программное обеспечение «ServerMonitor Enterprise v2.0», разработанное в рамках учебной практики по профессиональному модулю ПМ.03 «Ревьюирование программных модулей».
Программный комплекс предназначен для автоматизации учета серверной инфраструктуры, оперативного контроля утилизации вычислительных ресурсов (процессорного времени, оперативной памяти, сетевых задержек) и проведения вычислительных экспериментов по прогнозированию отказоустойчивости кластера при пиковых нагрузках.

1.2. Краткое описание возможностей
• Аутентификация пользователей с проверкой учетных данных в реляционной базе данных SQLite и отображением активной сессии администратора.
• Регистрация новых серверных узлов с указанием сетевых реквизитов (имя хоста, IP-адрес), функциональной роли (Web-сервер, База данных, API-шлюз, Резервное копирование, Аналитика БД) и текущих метрик производительности.
• Автоматический расчет комплексного индекса риска отказа узла и присвоение статуса состояния («Стабильно», «Высокая нагрузка», «Критично»).
• Фильтрация списка серверов по текущему статусу работоспособности и удаление неактуальных записей из базы данных.
• Экспорт сводной таблицы мониторинга в формат CSV (с разделителем «точка с запятой» в кодировке UTF-8 с BOM) для последующей обработки в Microsoft Excel.
• Проведение встроенного вычислительного эксперимента: моделирование роста входящего трафика на заданный коэффициент с расчетом прогнозируемой нагрузки CPU/RAM, вероятности отказа каждого узла и формированием рекомендаций по масштабированию.

1.3. Уровень подготовки пользователей
Для успешной эксплуатации программного комплекса конечный пользователь должен обладать базовыми навыками работы на персональном компьютере под управлением ОС семейства Microsoft Windows или Linux:
• Умение работать с стандартными манипуляторами ввода (клавиатура, мышь).
• Навыки навигации в графическом оконном интерфейсе (заполнение текстовых полей, работа с выпадающими списками, переключение вкладок).
• Базовое понимание параметров серверного администрирования (загрузка CPU, объем ОЗУ, сетевой пинг).
Специальных знаний в области программирования и прямого администрирования СУБД SQLite не требуется.

1.4. Перечень эксплуатационной документации
В комплект эксплуатационной документации программной системы входят:
1. Настоящий документ: «Руководство пользователя» (user_guide.txt).
2. Исходный код программных модулей: server_monitor_v1.py (базовая редакция) и server_monitor_v2.py (окончательная редакция).
3. Файлы локальных реляционных баз данных SQLite: servers_v1.db и servers_v2.db.

2. Назначение и условия применения
2.1. Виды деятельности и функции
Программа обеспечивает выполнение следующих производственных функций системного администратора и инженера-аналитика:
• Инвентаризация и ведение реестра серверного оборудования;
• Оперативный мониторинг и диагностика критических состояний узлов;
• Имитационное нагрузочное тестирование инфраструктуры и оценка рисков отказа (SLA);
• Формирование табличной отчетности по состоянию вычислительного кластера.

2.2. Программные и аппаратные требования к системе
Аппаратные требования:
• Процессор: двухъядерный Intel Core / AMD с тактовой частотой не ниже 1.6 ГГц.
• Оперативная память (ОЗУ): не менее 2 ГБ.
• Свободное дисковое пространство: не менее 50 МБ для размещения интерпретатора, исполняемых скриптов и файлов БД.
• Устройство отображения: монитор с разрешением экрана от 1024x768 точек.
Программные требования:
• Операционная система: Microsoft Windows 10/11, Linux или macOS.
• Установленный интерпретатор Python версии 3.8 или выше со стандартными встроенными библиотеками (tkinter, sqlite3, csv).

3. Подготовка к работе
3.1. Состав дистрибутива
Дистрибутивный комплект окончательной версии программного обеспечения включает следующие компоненты:
• server_monitor_v2.py — основной исполняемый модуль приложения с графическим интерфейсом.
• servers_v2.db — файл реляционной базы данных SQLite, содержащий таблицы учетных записей (users) и серверных узлов (servers). При отсутствии файла в директории он генерируется автоматически при первом запуске.
• user_guide.txt — файл эксплуатационной документации.

3.2. Запуск системы
1. Перейдите в рабочий каталог проекта, содержащий файл server_monitor_v2.py.
2. Запустите программу двойным щелчком левой кнопки мыши по файлу либо через терминал командой: python server_monitor_v2.py
3. На экране отобразится стартовое диалоговое окно «Авторизация — ServerMonitor Enterprise v2.0».
4. Введите учетные данные администратора (по умолчанию: логин — admin, пароль — admin123) и нажмите кнопку «Войти в систему».

3.3. Проверка работоспособности
Успешный запуск и готовность системы к работе подтверждаются следующими признаками:
• Закрытие окна авторизации и открытие главного окна «ServerMonitor Enterprise v2.0 — Диагностика и нагрузочное моделирование».
• Отображение в правом верхнем углу экрана информации о текущей сессии: «Пользователь: Ивангин С. Р. (Системный администратор)».
• Загрузка списка серверных узлов в таблицу вкладки «Мониторинг и учет узлов» и отображение сводной статистики в нижней строке состояния.

4. Описание операций
Операция 4.1. Авторизация пользователя в системе
• Наименование: Вход в программный комплекс под учетной записью администратора.
• Условия выполнения: Приложение запущено, отображается окно авторизации, база данных servers_v2.db доступна для чтения.
• Подготовительные действия: Уточнить актуальный логин и пароль администратора.
• Основные действия: Заполнить поля «Логин администратора» и «Пароль», нажать кнопку «Войти в систему».
• Заключительные действия: Система выполняет SQL-запрос к таблице users, проверяет корректность пары логин/пароль, закрывает окно входа и открывает основной интерфейс с привязкой ФИО пользователя.
• Ресурсы, расходуемые на операцию: Время оператора — 5–10 секунд; процессорное время — менее 0.05 секунды; ОЗУ — ~18 МБ.

Операция 4.2. Регистрация нового серверного узла и расчет индекса риска
• Наименование: Добавление записи о сервере в базу данных SQLite.
• Условия выполнения: Пользователь авторизован, активна вкладка «Мониторинг и учет узлов».
• Подготовительные действия: Собрать данные о новом сервере (имя хоста, IP-адрес, роль, процент загрузки CPU и RAM, время отклика ping в миллисекундах).
• Основные действия: В блоке «Регистрация нового сервера» заполнить текстовые поля, выбрать функциональную роль из выпадающего списка и нажать кнопку «Добавить узел».
• Заключительные действия: Программа валидирует числовые значения, вычисляет взвешенный индекс риска отказа, присваивает статус узлу, сохраняет запись в таблицу servers базы данных servers_v2.db, очищает поля ввода и обновляет таблицу.
• Ресурсы, расходуемые на операцию: Время оператора — 15–20 секунд; дисковые операции записи в БД (~2 КБ); ОЗУ — ~2 МБ.

Операция 4.3. Фильтрация и удаление записей из реестра
• Наименование: Отбор узлов по состоянию и удаление списанных серверов.
• Условия выполнения: В таблице мониторинга присутствуют записи.
• Подготовительные действия: Определить целевой статус для фильтрации или выбрать конкретную строку в таблице нажатием левой кнопки мыши.
• Основные действия: Для фильтрации выбрать значение в выпадающем списке «Фильтр по статусу» («Все», «Стабильно», «Высокая нагрузка», «Критично»). Для удаления выделить нужный сервер в таблице и нажать кнопку «Удалить выбранный».
• Заключительные действия: Таблица динамически перестраивается, при удалении запись стирается из БД, а сводная статистика в нижней части окна пересчитывается.
• Ресурсы, расходуемые на операцию: Время оператора — 3–5 секунд; процессорное время — менее 0.05 секунды.

Операция 4.4. Экспорт данных мониторинга в формат CSV
• Наименование: Выгрузка текущего реестра серверов во внешний табличный файл.
• Условия выполнения: Пользователь авторизован, база данных содержит записи.
• Подготовительные действия: Нажать кнопку «Экспорт в CSV» в правой части панели инструментов.
• Основные действия: В стандартном диалоговом окне сохранения файла выбрать каталог назначения, задать имя файла (по умолчанию server_report.csv) и нажать «Сохранить».
• Заключительные действия: Программа формирует CSV-файл в кодировке UTF-8 с BOM, записывает заголовки и все строки из таблицы servers, после чего выводит информационное окно об успешном завершении экспорта.
• Ресурсы, расходуемые на операцию: Время оператора — 5–10 секунд; дисковое пространство — ~5–15 КБ.

Операция 4.5. Проведение вычислительного эксперимента (нагрузочное моделирование)
• Наименование: Стресс-тестирование серверного кластера при пиковом росте трафика.
• Условия выполнения: В базе данных зарегистрирован хотя бы один серверный узел.
• Подготовительные действия: Переключиться на вкладку «Вычислительный эксперимент (Стресс-тест)».
• Основные действия: В поле «Коэффициент пикового роста трафика» задать множитель нагрузки (например, 1.35, что соответствует росту трафика на 35%) и нажать кнопку «Запустить моделирование кластера».
• Заключительные действия: Алгоритм считывает параметры всех серверов из БД, рассчитывает прогнозируемую утилизацию CPU, RAM и задержку сети, определяет вероятность отказа по каждому узлу, заполняет таблицу прогноза и выводит итоговое аналитическое заключение с рекомендациями по масштабированию в текстовое поле.
• Ресурсы, расходуемые на операцию: Время оператора — 5 секунд; процессорное время — менее 0.1 секунды; ОЗУ — ~22 МБ.

5. Аварийные ситуации
• Сообщение «Неверный логин или пароль!» при попытке входа. Причина: опечатка при вводе учетных данных, включенный режим Caps Lock или неверная раскладка клавиатуры. Действия по устранению: проверить раскладку клавиатуры (EN), отключить Caps Lock и повторно ввести данные учетной записи (admin / admin123).
• Сообщение «Поля CPU, RAM и Пинг должны содержать числа!» при добавлении сервера. Причина: ввод буквенных символов или пустых значений в числовые поля метрик. Действия по устранению: ввести корректные числовые значения (для дробных чисел использовать точку в качестве разделителя, например 45.5).
• Ошибка блокировки базы данных (sqlite3.OperationalError: database is locked). Причина: файл servers_v2.db открыт в стороннем редакторе баз данных в режиме монопольной блокировки. Действия по устранению: закрыть сторонние программы, использующие файл БД, и повторить операцию.
• Сообщение «Введите положительный коэффициент!» при запуске эксперимента. Причина: в поле коэффициента трафика введено отрицательное число, ноль или текст. Действия по устранению: указать положительное десятичное число больше нуля (например, 1.25 или 1.5).

6. Рекомендации по освоению
• Для наглядного изучения эволюции программного продукта рекомендуется сначала запустить первую редакцию системы (server_monitor_v1.py), оценить базовый функционал учета, а затем перейти к работе в окончательной версии (server_monitor_v2.py).
• При проведении вычислительного эксперимента рекомендуется протестировать работу кластера на нескольких коэффициентах нагрузки (например, 1.15, 1.35 и 1.80), чтобы определить порог устойчивости текущей инфраструктуры и выявить узкие места (серверы баз данных и аналитики).
• Рекомендуется регулярно выполнять экспорт состояния кластера в формат CSV перед проведением плановых технических работ или модернизации оборудования.
